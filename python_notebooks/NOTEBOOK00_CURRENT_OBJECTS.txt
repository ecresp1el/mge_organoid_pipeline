Notebook 00 Current Object State
================================

File described:
python_notebooks/notebooks/00_load_div30_div90_raw_to_anndata.ipynb

This note describes the checked-in frozen Notebook 00 state. Notebook 00 is now
intended to stop after loading, QC, filtering, and checkpoint creation.


High-Level Pipeline
-------------------

Notebook 00 currently does this:

1. Resolve selected sample/source paths.
2. Load each sample as its own AnnData object.
3. Concatenate loaded samples into one combined AnnData object.
4. Calculate QC metrics.
5. Save combined and per-sample QC plots.
6. Apply preliminary Scanpy filters:

       sc.pp.filter_cells(min_genes=20)
       sc.pp.filter_genes(min_cells=3)

7. Apply manual_ec biological/QC cutoffs.
8. Save combined filtered counts and normalized/log1p checkpoints.
9. Save matching per-sample filtered counts and normalized/log1p checkpoints.
10. Validate checkpoint assumptions and write validation tables.

Notebook 00 does not perform HVG selection, cell-cycle scoring,
CC.Difference creation, regression, scaling, PCA, neighbors, UMAP, clustering,
marker analysis, or integration.


Main Data Objects
-----------------

sample_adata_names
    List of loaded sample names.

    Example meaning:
    ["9853-MW-1", "9853-MW-2", ...]


sample_adata_list
    List of AnnData objects, one object per loaded sample.

    Important:
    These are the original loaded per-sample objects from the selected source.
    They are not the manual_ec-filtered checkpoint objects.
    They are used for per-sample source/QC inspection before concatenation.


adata_names
adata_list
    Backward-compatible aliases for:

    adata_names = sample_adata_names
    adata_list = sample_adata_list

    Prefer using sample_adata_names and sample_adata_list in new notebook cells
    because those names are more explicit.


combined_adata
    One combined AnnData object made by concatenating all objects in
    sample_adata_list.

    Status:
    - combined across samples
    - QC metrics calculated
    - not yet manual_ec-filtered at the time it is created
    - not normalized/log1p

    Combined QC plots use this object.


manual_ec_filtered_counts_adata
    One combined AnnData object after preliminary Scanpy filtering and
    manual_ec biological/QC filtering.

    Status:
    - combined across samples
    - QC/manual_ec-filtered
    - .X contains filtered raw counts
    - not normalized/log1p
    - no HVG annotation is created in Notebook 00

    This object is written to:

        results/notebook00/<RUN_LABEL>/h5ad/manual_ec_filtered_counts.h5ad


manual_ec_filtered_normalized_log1p_adata
    One combined AnnData object derived from manual_ec_filtered_counts_adata.

    Status:
    - same cells and genes as manual_ec_filtered_counts_adata
    - .X contains normalized/log1p expression
    - .layers["counts"] contains the filtered raw counts copied before
      normalization/log1p
    - no HVG annotation is created in Notebook 00

    This object is written to:

        results/notebook00/<RUN_LABEL>/h5ad/manual_ec_filtered_normalized_log1p.h5ad


manual_ec_adata
adata
    Backward-compatible aliases for:

        manual_ec_adata = manual_ec_filtered_counts_adata
        adata = manual_ec_filtered_counts_adata

    In frozen Notebook 00 these aliases point to the filtered counts state, not
    the normalized/log1p state.


Combined Checkpoint Files
-------------------------

All checkpoint files are saved under the dynamic run label:

    results/notebook00/<RUN_LABEL>/h5ad/

Combined files:

    manual_ec_filtered_counts.h5ad
    manual_ec_filtered_normalized_log1p.h5ad

The counts file stores:

    .X = QC/manual_ec-filtered raw counts

The normalized/log1p file stores:

    .X = normalized/log1p expression
    .layers["counts"] = QC/manual_ec-filtered raw counts


Per-Sample Checkpoint Files
---------------------------

Per-sample checkpoint files are saved under:

    results/notebook00/<RUN_LABEL>/h5ad/per_sample/

For each run_sample_id:

    <run_sample_id>.manual_ec_filtered_counts.h5ad
    <run_sample_id>.manual_ec_filtered_normalized_log1p.h5ad

Each per-sample counts file is a one-sample slice of the combined filtered
counts checkpoint.

Each per-sample normalized/log1p file is the matching one-sample slice of the
combined normalized/log1p checkpoint.

The .X and .layers["counts"] meanings are identical to the combined checkpoint
pair.


Validation Tables
-----------------

manual_ec_checkpoint_summary_df
    One row for the combined checkpoint pair and one row per sample.
    Records file paths, object dimensions, target_sum, and the intended matrix
    state for .X and .layers["counts"].

    Written to:

        results/notebook00/<RUN_LABEL>/tables/manual_ec_checkpoint_summary.tsv


manual_ec_checkpoint_validation_df
    One row for the combined checkpoint pair and one row per sample.
    Checks the checkpoint assumptions:

    - counts and normalized/log1p objects have matching obs names
    - counts and normalized/log1p objects have matching var names
    - counts .X is nonnegative
    - normalized/log1p .X is nonnegative
    - normalized/log1p object contains .layers["counts"]
    - .layers["counts"] matches the counts object's .X
    - checkpoint metadata records the expected .X state
    - expected .h5ad files exist

    The notebook raises an AssertionError if any
    checkpoint_validation_passed value is False.

    Written to:

        results/notebook00/<RUN_LABEL>/tables/manual_ec_checkpoint_validation.tsv


Recommended Downstream Starting Points
--------------------------------------

Use manual_ec_filtered_counts_adata or the counts checkpoint files when:
    You need raw counts after QC/manual_ec filtering.
    Notebook 01 should start Seurat-v3 HVG selection from this count state.

Use manual_ec_filtered_normalized_log1p_adata or the normalized/log1p
checkpoint files when:
    You need normalized/log1p expression and still want raw counts available in
    .layers["counts"].

Use sample_adata_list when:
    You want to inspect the original loaded samples before manual_ec filtering.
