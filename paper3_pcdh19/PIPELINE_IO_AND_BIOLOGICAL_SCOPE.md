# Paper 3 Pcdh19 probe audit: inputs, outputs, and biological scope

This document is the I/O contract for the locked `02a_pcdh19_probe_audit`
workflow. It describes every executable used by this step, the meaning of its
files, and the boundary between an observed probe pattern and a biological
interpretation.

The registered source tissue is mouse embryonic brain, MGE, and the dataset was
generated with 10x Flex v2. This audit asks a deliberately narrow question:
which of the three panel probes assigned to Pcdh19 produced raw UMIs in each
Cell Ranger filtered barcode? The delivery itself did not identify genotype or
sex. A user-provided sample key was registered after the technical audit in
`config/sample_key.csv`. Those biological fields remain absent by design from
every input and output in the frozen Step `02a`; they are joined only in later
biological analysis.

The validated production output was generated by pipeline version `1.0.0`
with this frozen implementation:

```text
paper3_pcdh19/scripts/pcdh19_probe_audit.py
SHA-256 731edca099bcbca8fb5e968ed621c2e5d8e31e3f25b6209b5008d2eb082d7b43
```

Do not edit that Python file and claim that the existing results came from the
edited implementation. Its exact checksum is recorded in
`software_environment.tsv`. A computational change requires a new pipeline
version and a newly validated output package.

## Workflow position

- `00_source_discovery`: located the correct `15662-JZ` delivery; complete.
- `01_sample_key`: user-provided mapping registered; complete, with
  experimental-unit details still to confirm.
- `02_input_audit`: broader delivery and canonical-input audit; not complete.
- `02a_pcdh19_probe_audit`: this locked, technical-only workflow; complete.

Step `02a` intentionally runs without ingesting the sample key because it uses
only technical IDs. This keeps the validated assay audit separate from later
biological annotation. It does not replace the broader Step `02`.

## Scientific object being measured

The workflow audits three 10x Flex probes assigned to mouse `Pcdh19`
(`ENSMUSG00000051323`) in the delivered Chromium Mouse Transcriptome Probe Set
v2.0.0, GRCm39, reference 2024-A:

| Label | Probe suffix | Validated target position | Meaning in pattern names |
| --- | --- | --- | --- |
| `A` | `a3f4e22` | Entirely exonic; exon 1 in all three targeted transcripts | Exon-1 probe detected when `A_UMI > 0` |
| `B` | `8215225` | Entirely exonic; exon 2 or 3 depending on targeted transcript | Downstream probe detected when `B_UMI > 0` |
| `C` | `d013e0b` | Entirely exonic; exon 4 or 5 depending on targeted transcript | Downstream probe detected when `C_UMI > 0` |

Their validated 5-prime-to-3-prime order along the negative-strand Pcdh19 gene
is `A`, `B`, `C`. The value `region=unspliced` is retained exactly as a 10x
probe annotation. It does **not** mean that these targets are intronic; the
coordinate audit establishes that all three targets are exonic.

An UMI is a deduplicated molecule count reported by Cell Ranger. A zero means
that no UMI was observed for that probe in that barcode. It does not prove
that the underlying transcript sequence or biological state is absent.

## Authoritative scientific inputs

The runner obtains paths from `config/greatlakes.env` and expected identities
from `config/pcdh19_probe_audit.lock.json`. All reference identities are
checksum-locked.

| Input | Role |
| --- | --- |
| Delivered `probe_set.csv` | Establishes the exact panel delivered with this Cell Ranger run and the three full Pcdh19 probe IDs, sequences, and 10x `region` values. |
| Matching 10x BED12 | Supplies exact GRCm39 target intervals, BED strand, and blocks for the same v2.0.0/2024-A probes. |
| Matching 10x probe metadata TSV | Supplies `transcript_id_set` for the exact probe IDs. |
| GRCm39-2024-A `genes.gtf.gz` | Supplies Pcdh19 gene, transcript, exon, and strand annotations used for the exon intersections. |
| GRCm39-2024-A `reference.json` | Confirms the Cell Ranger reference version, `mkref` version, and input GTF identity. |

For each technical sample `15662-JZ-1` through `15662-JZ-12`, the workflow
reads three Cell Ranger files from `per_sample_outs/<sample_id>/`:

| Cell Ranger input | How it is used |
| --- | --- |
| `sample_raw_probe_bc_matrix.h5` | Source of raw integer UMI counts for the three exact probe features. Only columns marked by Cell Ranger as filtered barcodes are extracted. This is the source of `A_UMI`, `B_UMI`, and `C_UMI`. |
| `sample_filtered_feature_bc_matrix.h5` | Independent filtered gene-level matrix. Its Pcdh19 row is used to validate the reconstructed three-probe count for every barcode and for the whole sample. It is not the source of the individual probe counts. |
| `sample_filtered_barcodes.csv` | Defines the filtered-cell denominator and required barcode order. It is compared exactly with the filtered barcodes in both HDF5 inputs. |

No FASTQ, Loupe projection, UMAP, cluster assignment, genotype table, sex,
condition, donor, cell-line, or sample-key field enters the frozen Step `02a`
workflow. The registered CSV is a separate downstream annotation input.

## Executables and their I/O

### `bin/check_candidate_access.sh`

Purpose: read-only source discovery support for Step 00.

- Input: `config/input_candidates.tsv`, optionally replaced by `--manifest`;
  `--max-depth` controls the metadata scan depth.
- Reads: path existence, permissions, file counts, and byte sizes through the
  requested depth. It does not read scientific matrix contents.
- Output: a TSV inventory on standard output only.
- Biological use: none. It can establish that a candidate delivery is present
  and accessible, but not what biological condition any sample represents.

### `bin/initialize_turbo.sh`

Purpose: create the Paper 3 output directory skeleton.

- Input: `config/greatlakes.env`, `templates/TURBO_ROOT_README.md`, and the
  repository `HANDOFF.md`.
- Output: `inputs/`, `results/`, `logs/`, `jobs/`, and `final_figures/` under
  `PAPER3_ROOT`, plus copied README and handoff files.
- Side effect: creates directories and copies documentation; it does not read
  or transform expression data.
- Biological use: none.

### `bin/run_pcdh19_probe_audit_all.sh`

Purpose: the supported local/interactive entry point for Step `02a`.

- Inputs: `config/greatlakes.env`, the JSON reference/prototype lock, pinned
  Python requirements, the frozen Python implementation, the exact reference
  files, and the three per-sample Cell Ranger files listed above.
- Environment: requires Python 3.6, h5py 3.1.0, and NumPy 1.19.5. Missing
  pinned packages are installed into a workflow-specific directory below
  `PAPER3_ROOT/software/`; source matrices are not modified.
- Outputs: the validated reference, per-sample, combined, environment, and
  checksum files described below, plus a timestamped run log.
- Restart behavior: verifies and retains byte-identical validated outputs;
  refuses incomplete, checksum-failing, or different existing outputs.
- Biological use: enumerates observed probe counts and binary combinations.
  It does not assign a biological identity to a sample or cell.

Additional arguments are passed to the Python program. For example,
`--prototype-only` stops after recreating and checking `15662-JZ-1`.

### `slurm/pcdh19_probe_audit_all.sbatch`

Purpose: Great Lakes batch wrapper for the same supported runner.

- Input: the repository checkout and all inputs required by
  `bin/run_pcdh19_probe_audit_all.sh`.
- Scheduler resources: account `parent0`, standard partition, 2 CPUs, 8 GB
  memory, and a four-hour limit.
- Output: a scheduler log in `PAPER3_ROOT/logs/` and the same scientific output
  package as the local runner. It contains no separate analysis logic.
- Biological use: identical to the local runner; scheduling does not change
  interpretation.

### `scripts/pcdh19_probe_audit.py`

Purpose: frozen computational implementation. Supported subcommands are:

| Command | Action and output |
| --- | --- |
| `references` | Validates/downloads only the locked reference files and writes the two reference output tables. |
| `sample --sample-id 15662-JZ-N` | Validates references and processes one allowed technical sample. JZ-1 is automatically checked against the frozen prototype. |
| `combine` | Requires all 12 validated per-sample directories, then produces combined tables and the output manifest. |
| `run-all` | Validates references, gates on exact JZ-1 reproduction, processes JZ-2 through JZ-12, and combines all outputs. This is the normal command used by the shell runner. |

Required CLI inputs are `--lock`, `--cellranger-root`, and `--paper3-root`.
The GTF and `reference.json` paths are supplied through
`PAPER3_GRCM39_GTF` and `PAPER3_GRCM39_REFERENCE_JSON`.

The program uses temporary files/directories, validates before publication,
uses atomic renames, and refuses to overwrite different existing artifacts.

## Output files and data meaning

Production root:

```text
/nfs/turbo/umms-parent/mgeo_neuron_scrnaseq_projectfolder/paper3_pcdh19/results/pcdh19_probe_audit
```

### Reference outputs

`references/pcdh19_probe_coordinates.tsv` contains one row per probe, including
the full probe ID and sequence, 10x annotation, 0-based half-open BED interval,
BED12 blocks, targeted transcripts, GTF exon assignments, gene strand, and
5-prime order.

`references/reference_manifest.tsv` records the role, version, source,
resolved path, byte size, SHA-256, and validation result for every reference
input and the derived coordinate table.

### Per-sample barcode table

`per_sample/<sample_id>/pcdh19_probe_patterns.tsv` has exactly one row for each
filtered barcode:

| Column | Meaning |
| --- | --- |
| `barcode` | Cell Ranger filtered barcode; technical identifier only. |
| `A_UMI` | Raw UMI count for exon-1 probe `a3f4e22`. |
| `B_UMI` | Raw UMI count for downstream probe `8215225`. |
| `C_UMI` | Raw UMI count for downstream probe `d013e0b`. |
| `Pcdh19_total_UMI` | Exact integer sum `A_UMI + B_UMI + C_UMI`; checked against the Cell Ranger gene-level Pcdh19 count. |
| `detection_pattern` | One of `A+B+C`, `A+B`, `A+C`, `A only`, `B+C`, `B only`, `C only`, or `none`, based only on whether each raw count is greater than zero. |

Counts are not normalized, log-transformed, imputed, ambient-RNA-corrected, or
adjusted for sequencing depth.

### Per-sample summary and validation

`pcdh19_probe_summary.tsv` uses `summary_type` to distinguish:

- `probe`: total UMI, detected cells, fraction/percent of filtered cells, mean
  UMI among detected cells, and maximum UMI per cell for A, B, or C;
- `gene_reconstruction`: summed three-probe Pcdh19 UMI and number/fraction of
  cells with any Pcdh19 detection;
- `pattern`: counts and percentages for all eight patterns, percentage among
  Pcdh19-detected cells, and median/mean/maximum total Pcdh19 UMI;
- `downstream_A_status`: exon-1-positive and exon-1-negative counts/fractions
  among cells with `B or C` detection; and
- `downstream_BC_A_negative`: the exact `B+C`/A-negative combination.

`validation.tsv` contains machine-readable `PASS`/`FAIL` checks. These include
barcode equality and uniqueness, per-cell and sample-total agreement with the
Cell Ranger Pcdh19 row, eight-pattern partition totals, probe marginals, and
serialized-output checks. JZ-1 also includes frozen prototype totals, pattern
counts, and byte-equivalence.

`checksums.sha256` protects the three published per-sample TSV files.

### Combined and provenance outputs

- `combined/all_samples_pcdh19_probe_summary.tsv`: concatenated probe and gene
  reconstruction rows for all technical samples.
- `combined/all_samples_pcdh19_pattern_summary.tsv`: concatenated pattern and
  downstream-status rows for all technical samples.
- `combined/all_samples_validation.tsv`: all validation rows.
- `software_environment.tsv`: pipeline/Python/package versions and checksums
  of the frozen Python implementation and reference lock.
- `output_manifest.tsv`: byte size and SHA-256 for every published output.

## Valid uses of the frozen technical output

The current outputs may be used to:

- verify exact probe identity, sequence, coordinates, transcripts, and exons;
- verify that raw probe counts reconstruct Cell Ranger Pcdh19 counts;
- describe technical-sample probe-detection frequencies and combinations;
- identify technical patterns that should be checked against the eventual
  biological design; and
- audit pipeline reproducibility and input consistency.

After an explicit join to `config/sample_key.csv`, the technical sample rows
may also be summarized by the four registered design groups. Such joined
tables are new downstream artifacts; they must not be presented as outputs
that were generated by the frozen probe-audit pipeline.

## Uses that still require additional biological design or analysis

Do not use the probe-audit output alone to:

- call an A-negative downstream-positive cell a mutant cell;
- infer genotype, allelic state, transcript genotype, or editing status;
- treat the submitted samples as independent biological replicates without
  confirmation of embryo/donor/litter/batch structure;
- claim differential expression, cell-type specificity, or biological effect;
- infer absence of exon 1 from a zero probe count; or
- perform a full genotype-by-sex interaction analysis when HET males and KO
  females are absent from the registered design.

The registered mapping now supports planning the sex-matched HET-female versus
WT-female and KO-male versus WT-male comparisons. Formal inference still
requires confirmation of experimental units and an appropriate sample-level
analysis. Binary probe non-detection must be modeled as an observation subject
to capture efficiency and sampling, not treated alone as proof of a cell's
genotype. Biological conclusions require the replicate structure, appropriate
denominators, and orthogonal validation where the claim demands it.
